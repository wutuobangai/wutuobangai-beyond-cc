# 教训别让 AI 全背：编号找路，踩坑技能管动作

> 作者：阿浩 · 2026-11-18 · 2026 年 11 月版

> 我把共同教训做成编号索引，每条业务再留一个踩坑技能。任务碰到哪类问题，就回哪条原文，不让 AI 每次把事故大全通读一遍。

出过一次错，写一条提醒，这个动作很容易。难的是下次真碰到同样的事，AI 能不能找到，找到后会不会改变做法。我现在要求教训留下来源、触发词和下一次动作。只写一句「以后注意」，当时看着认真，换个窗口就不知道该注意什么了。

## 真实场景：自动附上的经验不等于新任务

我现在派工，任务命中相应业务时，会带上对应的踩坑经验。经验写「什么情况、当时发生什么、现在怎么做」，需要细节再回教训原文。共同教训只保留一份正文，两边都用同一个编号找过去。

| 读到什么 | 应该怎么用 |
|---|---|
| 教训编号与触发词 | 判断这次是否命中，定位原文 |
| 对应的最小正文 | 读全条件，确认下一步怎么做 |
| 业务踩坑技能 | 核这条业务特有的失败边界 |
| 旧事故里的数量与配置 | 只当历史，回当前证据重查 |
| 经验提到的其他问题 | 只作线索，不扩大本次施工 |

## 为什么要分这几层

索引负责找到东西，正文负责解释条件，技能把教训接到具体工作里。几者各干一件事，才不容易一改全乱。如果把完整事故塞进每个入口，更新一次就得找很多副本，还可能留着几个不同版本。

旧事故还有一个坑：当时的办法未必适合今天。机器、配置、工具都可能换了，不能看见一条历史经验，就直接恢复旧动作。教训要保留的是判断方法，比如先核真实入口、不要把自报完成当结果；具体数字仍得现查。

同样的错误再犯，我也不希望再加一条更凶的禁令。先查到底是没找到、理解错、没有执行，还是验证漏了，再改一个具体动作。否则规则越积越多，真正的问题还在。

## 你该怎么做

1. **给教训一个稳定编号。** 索引写清触发词、正文位置和适用范围，别把大段事故全文贴进去。
2. **保留可回查的来源。** 说清哪次事实形成这条经验，分开历史经过和当前有效做法。
3. **每条业务留一个踩坑入口。** 只收这条业务特别容易犯的错，共同规则指向正本，不重复抄。
4. **命中才读最小正文。** 读最小，不是断章取义；授权、例外和停止条件得一起读完。
5. **把动作接回开工。** 核 AI 在真实任务入口能找到并执行。再次犯错就更新原条，别靠新增同义提醒凑数量。

> 💡 自检：这条教训能不能告诉一个新 AI「什么时候用、先查什么、哪里必须停」？如果只剩「认真一点」，还没写到动作上。
