# AI 断线后怎么继续？留一份最小接续单

> 作者：阿浩 · 2026-11-26

AI 窗口断了，新窗口只记得你在做一个项目。它说“我继续”，然后把已经做过的步骤又跑一遍。文件可能被覆盖，原来停着的任务也可能重复启动。

接续时最该保住的，是你到底要什么、允许做什么，以及现在已经做到哪。聊天摘要可以辅助，但最好留一份能直接找回文件和结果的短单。

下面的“秋叶手册”是虚构项目。例子只演示怎样接续，不对应任何真实客户或业务。

## 留下能决定下一步的内容

一份接续单不需要复述整段聊天。把这几项写清，接手方才知道先查什么。

| 要留下什么 | 防什么问题 |
|---|---|
| 原始目标和已定条件 | 换窗口后自己改方向 |
| 已授权范围和禁项 | 把上轮的查证当成上线许可 |
| 文件、版本与检查结果 | 重做已经完成的部分 |
| 正在运行的任务 | 重复启动或误停别人的进程 |
| 未完、卡点和下一步 | 从一长串历史里猜进度 |

“已经写好”和“已经验过”分开。文件存下来了，只能证明有产物。正文是否完整、链接是否正确、功能是否可用，要写实际检查结果。没查就写待验。

## 可以直接复制的最小接续单

```text
项目：秋叶手册（示例）
更新时间：____
原始目标与完成条件：____
已定且本次不能改的条件：____
已授权动作与写入范围：____
禁止动作／仍需另行确认的动作：____

当前分支或文件版本：____
已完成产物：____（位置____）
已验证：____（实际结果____，证据位置____）
未验证：____

正在运行：____（任务标识____，输出位置____）
如何只读确认它仍在跑：____
已知卡点与试过的办法：____
下一步先做：____
继续前需要核实：____
尚需谁拍板：____
```

任务标识、日志和路径可能含私人信息。接续单放在项目允许的位置，不直接放进公开仓库；不要把密钥、登录信息或客户原话写进去。

## 新窗口先核，再续

第一步读原任务和接续单，确认目标没被摘要改写。第二步看真实文件、分支、输出时间和运行状态。单子说“正在生成”，不代表进程现在还活着；进程退出，也不代表结果已经合格。

确认没有重复执行风险后，才从“下一步”继续。如果另一个窗口还在改同一份文件，先交接写入权。找不到原任务或关键产物，就写明缺什么，不用重新生成整套来填空。

尤其是提交、发布、付款这类动作，先查有没有已经生效。状态不明时停相关动作，其他独立工作仍可以继续。接续单保存授权边界，不会因为写了“继续”就新增授权。

## 有新信息，就改接续单

比如原来写“等待资料”，后来资料补齐了，就更新这一项。不要在下面不断追加互相矛盾的“当前状态”，让下一位自己猜哪句新。

同样，别把临时进度塞进长期规则。固定要求管边界，接续单管这一件事的当前状态；长期经验另存到能查出处的地方。这样换窗口时，既能接上这次工作，也不会把某次未完当成永久指令。
