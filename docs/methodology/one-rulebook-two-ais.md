# 一份规矩两个 AI 共用：别养出两套说法

> 作者：阿浩 · 2026-11-18 · 2026 年 11 月版

> 规矩只写一份，两个 AI 从同一个地方读。
>
> 同一件事，我不想给 Claude 讲一遍，再给 Codex 讲一遍。讲两遍，迟早变成两个版本。

用两个 AI 以后，很容易顺手给它们各写一套规矩。开始看着方便，后来一边更新了，另一边还照着旧话做。我再纠正，两边又各加一句，越来越难知道哪句算数。我现在把共同要求放到一个正本里，各自的入口只保留工具和执行方式的差别。

## 真实场景：新窗口到底读了哪版

我的开工 hook 会自动注入同一块共同内容，带上来源更新时间和指纹。hook 可以理解成开工时自动跑的一步，把必需的规矩送进新会话。指纹则是用来核对内容是否相同的标记，不用肉眼逐段找区别。

| 遇到的情况 | 我现在怎么处理 |
|---|---|
| 两边对同一条边界说法不同 | 回共同正本核对，别各补一段 |
| 新窗口说已经知道规矩 | 看实际收到的开工块和来源标记 |
| 注入失败或内容省略 | 明说未知或省略，不能装作读全了 |
| 工具用法只有一边需要 | 留在各自入口，不塞进共同正文 |

## 为什么一份正本还不够

文件统一了，AI 却没读到，行为照样可能分叉。所以我分开看「规矩存在哪」和「这次会话收到什么」。来源时间与指纹给了回查线索，真正有没有读全，还得在新会话入口核。

我也给规矩排层级：老板本人、宪法、法律、条例。这里是我给内部规则起的名字，法律层放固定决定和安全红线，条例层放具体做法。具体手册不能另起一套权限，旧备份也不能冒充今天的正本。

统一不等于把全部资料塞进去。共同正文只讲两边都得遵守的边界，项目资料、岗位经验按任务再读。否则入口越长，越容易截断，真正要用的那句反而到不了眼前。

## 你该怎么做

1. **先定唯一正本。** 明确哪份共同规矩负责授权、交付和沟通；其他入口只指过去，别再复制整篇。
2. **写清层级。** 当轮明确要求、长期规则和具体操作手册分别管什么，发生冲突先回原话及有效规则。
3. **自动带入最小必读。** 两边从同一来源生成开工内容，附来源时间与内容标记；生成结果不再手工各改各的。
4. **核实际接收。** 在各自新会话里查看收到的内容，失败和截断要暴露出来，不能只检查配置写没写。
5. **改一次，再核两边。** 更新正本后检查两个入口，旧版本留作历史，别把历史说明当成当前指令。

> 💡 自检：明天我只改一条共同规矩，两边能不能收到同一句话，并说清它来自哪版？
