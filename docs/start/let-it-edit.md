# 让它帮你改东西：不慌、能撤回

> 这篇结束，你会：放心让 Claude Code / Codex 直接改你电脑里的文件——因为你已经学会改之前先看、改错了能撤回。从此它不只是"给你出主意"，而是真帮你动手。

## 先搞懂一件事：它是真会动手的

网页上的 AI（比如打字聊天那种），最多**告诉你**「你应该这样改」，剩下的还得你自己一个字一个字去改。

Claude Code 和 Codex 不一样——它们住进了你电脑里，**能直接打开你的文件、把内容改掉**。你说「帮我把这份笔记整理成清单」，它是真的去改那个文件，不是嘴上说说。

> 这就是它值钱的地方：**从"出主意"升级成"真干活"**。但也正因为它真能动你的东西，你得先学会怎么稳稳地用它。

## 它改之前，会先给你"看一眼"

这是最让人安心的设计：**它动手之前，会先把"要改哪、改成啥样"摆给你看，等你点头才改。**

你会在屏幕上看到类似这样的对比——程序员管它叫 **diff（改动对比）**，你不用记这个词，看懂就行：

```diff
  这是没动的一行（原样保留）
- 这是它要删掉的旧内容
+ 这是它要换上去的新内容
  这也是没动的一行
```

记住两个符号就够了：

- **红色、前面带 `-`** 的行 = 它要**删掉 / 换掉**的旧内容
- **绿色、前面带 `+`** 的行 = 它要**新加 / 换上**的新内容
- 没颜色、没符号的 = 没动，原样不变

> 你只要扫一眼：删的对不对？加的是不是你要的？对了就放行，不对就喊停。**不用看懂每个字，看明白"它要把哪改成哪"就行。**

## 安全感从哪来：3 个动作

很多人不敢让 AI 改自己东西，怕改坏。其实只要养成这 3 个习惯，心里就有底了：

### 1. 改之前，先备份

让它动重要文件前，先留个底。最简单的办法——**让它先把文件复制一份再改**。你可以直接跟它说：

> 「改之前先把这个文件复制一份，加个 `.bak` 的名字留底，再改。」

这样万一改砸了，那份 `.bak` 就是你的后悔药。

### 2. 看明白再放行

它弹出 diff 问你「可以吗」时，**别闭着眼狂点同意**。停一秒，看一眼上面那个对比，确认删的、加的都对，再点同意。养成"先看再点"这一下，省掉绝大多数翻车。

### 3. 改错了，能让它改回去

万一真改得不对，别慌，你有两条退路：

- **让它自己改回来**：直接说「这步改错了，恢复成原来的样子」——它会还原。
- **用刚才的备份**：让它「用那份 `.bak` 把文件还原回去」。

> 还有一招更稳的：如果你的文件夹用了 **Git**（一种版本记录工具，进阶会学），那它每一步改动都有记录，随时能退回任意一个版本。现在不懂没关系，**先靠"备份 + 看 diff"这两招就够安全了**。

## 破除最大的担心："它会不会把我东西改坏？"

这是每个新手第一次的心结。说点实在的：

- 它**不会偷偷改**——动手前会先问你、先给你看 diff。
- 它改的是**你指定的那个文件**，不会乱碰别的（除非你让它碰）。
- 就算真改错了，只要你**备份了 / 看了 diff / 留着原文件**，全都能找回来。

> 换句话说：**会不会改坏，主动权在你手里**，不在它手里。你先看、先备份，它就翻不了大浪。

## 新手最容易卡的地方（我当年的真实经历）

**第一次让它改我自己的文件时，我手是抖的。** 那是一份我攒了好久的资料，我盯着那个「是否同意修改」的提示，愣是不敢点——万一它给我搞乱了呢？

后来我学乖了，就两步：

1. **先在不重要的地方练手**：我新建了一个空文件夹，往里丢几个随便的测试文件，让它在那里面随便改。改坏了也不心疼。练几次，手感就有了。
2. **强迫自己"先看 diff 再点同意"**：一开始嫌麻烦，总想直接点过去。逼自己看了几次之后才发现——这一眼太值了，有两次它要动到我没想让它碰的地方，就是这一眼拦下来的。

> 现在这成了我的肌肉记忆：**它问"可以吗"，我必先扫一眼 diff，再决定。** 你也照这么练，很快就不慌了。
